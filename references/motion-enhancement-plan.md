# 组件动效增强计划与验收标准

日期：2026-10-14。项目：`ui-builder-xtn`。

本文保留本轮动效增强的范围与验收标准。**P1–P6 本地实现与限定验收已完成**。实时执行状态、原始失败、通过证据的源码身份及覆盖边界只记录在 organizer 的 `execution-state.json`，本文不另建进度台账。原计划仅负责本地开发；2026-10-14 用户另行批准将已验收主题、动效及后续修复交付到 `main` 与 GitHub Pages，固定版本与已有 Release 附件保持不变。下方原验收记录保留其当时的源码身份和本地阶段边界。

## 1. 目标与当前情况

目标：让官方组件的出现、消失、展开和状态变化自然、统一，同时保持尺寸、焦点、计时和业务逻辑可靠。使用者安装组件后即可获得默认动效，无须自己写动画 CSS、包一层动画组件或安装额外动画库。

制定计划时的基线已存在按钮/输入框状态过渡、Switch 滑块、Progress、Spinner、Collapse 箭头及 Toast 倒计时。以下记录的是实现前的主要缺口；本轮已在对应官方路径接入，实际通过情况以唯一台账为准：

- Dialog、Drawer 根据 `open` 直接卸载，缺少退出过程。
- Toast 关闭立即删除并补位，缺少退出占位与位置过渡。
- 菜单与提示浮层效果不统一；Tooltip 有进入淡入，但关闭通过 `display:none` 立即消失。
- Collapse 只转箭头，内容直接切换；动效时长分散，减少动效策略不完整。

基线与实现审阅入口：`assets/react-kit/src/ui/overlay/overlays.tsx`、`feedback/feedback.tsx`、`internal/layer-kernel.tsx`、`internal/floating-position.ts`、`internal/collapse.tsx`、`styles.css`、`styles/extended.css`、`styles/layout-actions-display.css`。基线 `src/explorer/cases/foundation/motion.guide.tsx` 仅展示基础状态过渡；本轮已扩展为可操作的真实组件动效预览，限定浏览器验收已完成。

## 2. 做哪些、不做哪些

| 组件范围 | 本轮效果与行为 |
| --- | --- |
| Dialog、ConfirmDialog | 遮罩淡入淡出；面板轻微淡入/缩放；完整退出生命周期 |
| Drawer | 桌面从右侧进入；移动端按现有底部抽屉方向进入；关闭反向退出 |
| Lightbox、GuidedTour | 共用浮层生命周期，补轻淡入淡出；保留图片切换、目标定位及关闭规则 |
| Toast / Snackbar | 出现、退出及同位置补位过渡；维持全局容量、队列、去重与计时 |
| Select、SearchableSelect、AsyncSelect、Combobox、Autocomplete、MultiSelect、TreeSelect | 菜单短淡入/淡出；不改变搜索、选择、异步结果及键盘模型 |
| DropdownMenu、ContextMenu、Popover、Tooltip | 统一轻浮层过渡；保留触发方式、定位、关闭与焦点规则 |
| Collapse | 内容高度平滑展开/收起，支持动态内容及中断；保留箭头反馈 |
| Button、输入框、Switch、Progress、Spinner、Skeleton 等已有动效 | 统一时序与减少动效规则；不追加装饰性动画 |

静态 Alert、Banner、Tag、表格行和普通页面内容不强行做进入动画。共享上述官方壳的组件继承其效果，不另写一套。此次不重做 Carousel、路由切换、拖放动画、图片切换特效、全站列表入场、主题设计或业务案例；不加入弹簧、视差、持续闪烁等效果。

## 3. 怎么做：统一技术规则

### 3.1 默认视觉与时序

| 类型 | 默认值 | 使用方式 |
| --- | --- | --- |
| 快速反馈 | 120ms | 悬停、聚焦色、轻菜单/Tooltip |
| 常规进入与位置过渡 | 180ms | Dialog、Toast、Popover、Toast 补位 |
| 较大位移/内容展开 | 220ms | Drawer、Collapse |
| 退出 | 轻菜单/Tooltip 100ms；常规 140ms；Drawer/Collapse 180ms | 比对应进入略快；同组遮罩与面板按较长者完成清理 |

进入缓动统一为 `cubic-bezier(0.2, 0, 0, 1)`，退出为 `cubic-bezier(0.4, 0, 1, 1)`；不增加人为延迟。Dialog 缩放不小于 0.98；轻浮层位移不超过 4px；Toast 不超过 8px。Drawer 按自身打开方向位移。加载旋转等持续指示保留原有有意义的周期，不强行改为 120–220ms。

时长、缓动由官方内部唯一配置拥有，并遵循现有 CSS layer/token 注册契约。JS 清理逻辑与真实 CSS 时长使用同一来源，不能再各写一个常量。默认不增加任意时长、位移、曲线等公共 Props，也不开放几何 token 给业务覆盖。

浮动组件优先使用 `opacity`、`transform`；禁止 `transition: all`。动画包装层与定位测量层分离，不能让 transform 改变 `floating-position` 的测量反馈。Collapse 是需要高度过渡的例外；只测量受影响内容，不逐帧扫描整个页面。

### 3.2 出现与消失生命周期

新增一个内部可中断 presence 能力，表达 `closed → entering → open → exiting → closed`。使用现有 React/CSS 能力实现，不引入动画依赖。公共 `open` 和 `onOpenChange` 仍保持现有含义：一次关闭请求只通知一次，不等动画结束再通知业务。

- 正常关闭后，退出完成才卸载；父级直接卸载则立即、幂等清理，不保证强制卸载有退出动画。
- 退出中重开复用同一实例与 layer 身份，取消旧完成回调、计时器和动画。旧代次事件不能卸载新打开的组件。
- 过滤子元素冒泡及无关属性的结束事件；不能只依赖 `animationend`/`transitionend`。事件遗漏时，按真实时长加 50ms 的有界兜底完成，单次退出清理不超过 400ms。
- 零时长、系统减少动效、document 已隐藏、动画取消均有明确完成路径；不得让已关闭组件持续占 DOM、锁滚动或困住焦点。
- SSR render 不读浏览器全局；客户端沿现有 Portal-ready 流程挂载。StrictMode 重复 effect 不留下监听、Observer 或计时器。

### 3.3 浮层与焦点

`useLayerKernel.active` 绑定 `present && portalTarget !== null`，包含退出阶段，也包含 Portal 就绪条件，避免初始 open/SSR hydration 时先激活却因没有 panel 跳过注册。进入时立即建立焦点管理；正常退出期间仍保持背景 inert、滚动锁与顶层所有权；退出完成一次性卸载、释放锁和恢复焦点。

退出期间阻止重复 dismiss 和新的提交/业务操作；不要提前对仍含焦点的 panel 设置 `inert` 或 `aria-hidden`。顶层正在退出时，连续 Esc 或点击不能穿透关闭父层、触发背景按钮。受控父级拒绝关闭、`closeOnBackdropClick`、`closable` 和嵌套层规则全部保留。

桌面 Drawer 仍上/右/下贴边、仅左侧圆角；移动端仍按现有底部抽屉契约。动画不能制造永久缝隙、额外边框或滚动条。

非模态菜单关闭时立即停止选择与键盘导航、解除 active-descendant 等逻辑关联。若焦点仍在待退出内容中，先按组件现有规则移到触发器或有效外部目标，再让退出内容 inert 并移出辅助技术访问；焦点已在外部时不抢回。退出的视觉副本不得抢焦点或作为可操作菜单暴露，也不套用模态焦点陷阱。

### 3.4 Toast 的容量、计时与补位

- 正在退出的提示继续占原容量与布局槽位；退出结束才删除，并按 FIFO 补位。动态调低上限仍不主动驱逐已显示提示。
- 等待项取消可直接移除。`dismissAll()` 先清空队列并停止计时，显示项完成退出，不能在退出后误补位；减少动效时立即完成。
- 排队不消耗 duration；首次可见挂载开始计时。进入动效计入显示时间，补位/重排不重置剩余时间。hover、focus、press、异步 action、页面隐藏等暂停原因继续成立。
- 开始退出就停止该项计时及操作。重复 dismiss 幂等；异步操作晚返回不能复活提示。去重键在提示实际移除前仍占用，保持原“不更新内容、不重置计时”契约。
- 同位置的存量项只移动，不重挂载、不重复播报，不丢失按钮焦点；三个位置的避让与滚动区域沿用现有规则。
- 进度条、读秒、自动关闭仍依据同一个剩余时间；减少动效不改变 duration，也不能停止真实倒计时逻辑。

### 3.5 减少动效与内容尺寸

尊重系统 `prefers-reduced-motion: reduce`，默认不新增独立的动效 Provider。减少动效时停用位移、缩放、展开和重排过渡，保留静态状态、加载文字及 ARIA；Spinner/Skeleton 停止非必要循环。Toast 进度、读秒仍准确反映时间，可离散更新而非平滑移动。

运行中切换减少动效，正在退出的元素立即完成；重新开启不重播已经完成的进入。Collapse 初始已展开不从零闪开；动态内容、换行和异步加载后高度自然更新，不能留下固定像素高度裁字。折叠时先将内部焦点移回触发器，再让内容退出键盘和辅助技术访问。

## 4. 分阶段执行与停止条件

| 阶段 | 工作与主要代码入口 | 验收后交付 |
| --- | --- | --- |
| P1：基础 | 内部时序、减少动效、presence；登记上表组件实际共享路径。仅在必要时调整 `layer-kernel` 接入 | 有界生命周期及中断契约；明确每个接入分支的归属 |
| P2：模态浮层 | `overlay/overlays.tsx`、`overlays-extra.tsx` 及 owned CSS；Dialog/Drawer/ConfirmDialog/Lightbox/GuidedTour | 能打开、退出、重开、嵌套的真实组件预览；关闭和焦点规则不变 |

| P4：非模态浮层 | `input/forms.tsx`、`inputs-extra.tsx`、overlay 家族及定位内部模块 | 所列菜单/搜索家族均接入；不出现定位抖动、无效焦点或退出后可选项 |
| P5：展开与基础反馈 | `internal/collapse.tsx` 与相关样式；收敛既有过渡/循环的减少动效行为 | 动态内容展开、快速反向操作、基础加载语义演示 |

按 P1→P6 顺序执行。只有与共享状态无冲突的样式/文档才并行；不让多个执行者同时改 presence、浮层内核和 Toast 队列。每阶段通过后停止该阶段检查并汇报“完成项、证据、阻断、下一步”，不报无依据百分比。

以下是预先限定的场景组，不是任意扩张的全量矩阵。可复用现有回归并增加有价值的断言；不为每条样式声明新建测试。

| 编号 | 场景 | 必须成立的结果 |

| A2 | 开→关→退出中重开；快速连续切换；受控拒绝关闭 | 最终 open 与 UI 一致；无提前卸载/回焦/解锁；拒绝关闭时不开始退出 |

| A10 | Collapse 初始展开、长内容、图片/异步高度更新、折叠中反向 | 不闪烁、不截断；稳定后恢复自然高度；折叠不把焦点留在隐藏内容 |

| A12 | SSR+hydration；嵌套主题 Portal；正式生产构建 | 无浏览器全局/hydration 警告；无新增来源绕过；安装源码包含动效实现 |

A1/A2/A5/A6/A11 的状态/时间边界优先用定向组件测试；浏览器只补焦点、真实动画、定位、布局及其无法替代的行为。A12 不开启全量安装器兼容矩阵：若安装机制未改，用源码 Manifest 绑定、完整性和实际 production verifier/build 证明交付；只有明确改到安装机制才登记额外安装检查。

### 5.1 视觉与浏览器采样

- Chromium 是主要交互/视觉入口。1440px 检查常规效果；320px 检查 Drawer、Toast、菜单、Collapse 的边界。不自动乘以全部宽度、主题、位置和状态。
- Firefox、WebKit 各仅跑两个具名核心回归：模态退出/重开与焦点锁；浮动菜单/Collapse 的结束清理及最终几何。若失败指向特定引擎再只补受影响分支，不默认运行整库。
- 默认浅色完成主要行为；Apple/磨砂深色只抽查一组模态与一组菜单，确认材质、圆角和 Portal 未受影响，不重做主题验收。
- 使用真实持续时间检查可感知的进入/退出；保留短录屏或带时间戳的过程采样，并人工查看。仅最终截图不算动效通过。
- 过程不得文字模糊到不可读、阴影出现矩形底、裁切圆角、控件压缩或跳到错误方向；结束后的布局与未加动效时一致，几何测量允许不超过 1 CSS px 的舍入误差。
- 对代表模态、菜单和 Toast 做受影响的键盘/ARIA 检查及定向 axe；不跑全站 axe。自动化不能替代实际焦点行为和视觉审阅。

### 5.2 检查预算与复用

1. 所有检查先登记精确命令、目录、输入身份、具名场景、超时和结果文件，经 `execution_guard.py execute` 执行。新浏览器检查先静态核对真实路由、公开 Props、定位目标、matcher 和焦点路径。
2. 每阶段最多启动一组所需定向组件检查、一组对应浏览器检查；修复后只复验失败或真正受影响的用例。单步首次加一次修复复验，最多两次；到限先汇报原因和调整计划，不换名字/目录绕过。
3. 单个组件检查组超时 120 秒；浏览器用例 30 秒、阶段浏览器命令 5 分钟；最终生产构建 5 分钟。超时先归类诊断，不自动重启原命令。首次执行前把实际可用的 runner/项目名落实到台账。
4. 分阶段使用现有开发预览和必要的定向类型检查；最终只做一次成功的 provenance/TypeScript/生产构建与受影响生成产物校验。若生产构建失败，修复后只按守卫预算复验，不借机增加全量门禁。
5. 失败先区分产品、消费者、工具、证据或环境；只有实际原因变化才重试。通过结果绑定真实源码指纹/命令，不把旧证据改标新源码。后续改了共享 presence，就复验它实际影响的场景；只改文档不重跑浏览器。
6. 禁止默认执行 `release:check`、无筛选 `test:components`/`test:browser`/`test:a11y`、完整 M8、hosted CI、候选打包或版本同步。本计划完成后的发布单独处理。

## 6. 最终交付与完成判定

本轮已交付：官方内部动效代码、各范围组件接入、必要的具名回归、中文优先的互动动效页、Skill 使用说明与契约、Unreleased 改动记录，以及台账中可追溯的结果和覆盖边界。
