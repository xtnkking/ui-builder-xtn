# 认证页与查询按钮修复（2026-10-12）

本次只处理通用认证页布局及输入框旁查询按钮的比例，基于 main `148f85ae545537798b5b8a566315da122d729e08`。组件实现、案例和使用说明一并调整；不创建版本、tag 或 Release。

## 认证页

原来的 `AuthenticationPage` 无论是否提供插画都保留桌面双列，并在 Explorer 中使用整页最小高度。其表单插槽直接排列输入框和按钮时，也没有官方表单间距。

- 无 `visual` 时使用居中的单列，内容最大宽度 420px；提供插画时才启用双列。
- 新增可选 `layout="page" | "embedded"`，默认 `page` 保留整页至少 100dvh；嵌入式最小高度为 `min(560px, 80dvh)`，长内容可继续增长。
- 按组件容器宽度响应：容器不超过 760px 时隐藏插画并收拢为单列，同样适用于宽屏中的窄面板。
- Explorer 的通用认证案例使用官方 `Form`、`Field`、`Input` 和 `Button`，输入框与按钮间隔 18px，按钮高度 44px；点击和 Enter 使用同一提交路径。
- 新增带插画案例，保留品牌家族登录案例及长内容案例。表单插槽继续由使用者组合，组件不额外包裹原生表单。

入口：`#/patterns/authentication` → 默认 → 通用认证页 / 带插画认证页。

## 查询按钮

按钮原本为隐藏的加载文案“处理中”和旋转图标预留宽度，导致两个字的查询操作看起来偏宽。本次采用已有公开属性：输入框旁使用 `size="field"`，并让 `loadingLabel` 与当前操作文字一致，例如“查询”“搜索”或英文 `Search`。旋转图标表示加载，按钮始终预留同一宽度。

- 中文查询组合在桌面约 83px 宽，与输入框同为 44px 高。
- 更新筛选栏、列表筛选及官方成员管理页面的查询组合；普通按钮的默认尺寸不变。
- 筛选栏默认案例模拟 800ms 请求，保留草稿/已应用条件的区别；加载期间保留已有结果，旋转图标可见，重复提交被同步请求门禁拦截。
- 移动端沿用组件已有重排和操作区宽度规则，无应用 CSS 覆盖。

入口：`#/components/filter-bar`、`#/patterns/list-filter`。

## 定向验证

新增 `assets/react-kit/tests/browser/auth-query-layout.spec.ts`，共四个 Chromium 案例：

1. 1440px / 320px 通用认证页居中、宽度上限、间距、无空白列及 Enter 提交。
2. 桌面插画双列、同一宽屏内的 320px 窄容器及移动端长内容。
3. 查询组合等高、紧凑宽度、草稿显式提交、移动端重排及列表查询按钮。
4. 查询旋转图标、加载前后尺寸不变及请求中的重复草稿提交拦截。

四项均通过，并查看桌面、移动端、插画及查询截图。源码完整性、API 兼容性、生成文档、案例静态证据、覆盖登记、模块边界、CSS 合同以及包含来源校验和 TypeScript 的 Vite 生产构建均通过。初次认证验证的错误路由/隐藏标签页定位失败，以及案例表达/组合命名的来源校验失败均保留；修正具体原因后只补验失败部分，未重复已通过的查询案例。
