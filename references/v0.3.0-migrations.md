# Personal UI v0.3.0 Migration Notes

These notes describe the reviewed `v0.3.0` breaking contracts against the immutable `v0.2.19` baseline. Publication status is established by the immutable release tag, GitHub Release, and completed release journal, not by this source snapshot; see [release process](release-process.md).

## Public control customization boundaries

Protected controls no longer expose raw `className`, `style`, CSS-in-JS props, DOM refs, owner markers, or arbitrary spread customization. Move application layout to a non-interactive wrapper and use the component's typed semantic props. Do not cast through `any`: the runtime sanitizer enforces the same boundary as TypeScript.

The usage policy also rejects every public-control JSX spread, including type-correct objects. TypeScript and provenance have distinct responsibilities; complete delivery must pass both. See [supported public usage](integration.md#supported-public-usage). This qualification preserves the explicit-prop policy and corrects the original roadmap's broader equivalence wording; it does not add spread support or change the public API.

```tsx
// v0.2.x: remove control-owned styling and the raw DOM ref.
const input = <Input className="wide-input" style={{ height: 52 }} ref={domRef} />;

// v0.3.0: layout belongs to the wrapper; the control owns its geometry.
const input = (
  <div className="account-field-layout">
    <Input aria-label="Account name" controlRef={controlRef} />
  </div>
);
```

Use `ControlHandle`, `TextControlHandle`, `ValidityControlHandle`, or `FormControlHandle` for the documented imperative surface. These handles provide operations such as `focus`, validity reporting, selection, form reset, and request-submit without exposing mutable component DOM.

```tsx
import { createRef } from "react";
import { Input, type TextControlHandle } from "./personal-ui";

const controlRef = createRef<TextControlHandle>();
const field = <Input aria-label="Account name" controlRef={controlRef} />;
controlRef.current?.focus();
void field;
```

## Controlled state, refs, and form adapters

Value and open state now use explicit controlled or uncontrolled unions. A controlled component supplies `value` plus its change callback, or `open` plus `onOpenChange`; an uncontrolled component supplies `defaultValue` or `defaultOpen`. Do not pass both channels or switch mode after mounting.

React Hook Form and similar controllers should use `controllerField`, which owns `name`, `value`, `onChange`, `onBlur`, and the limited handle ref as one binding. Do not combine it with direct value or ref props.

```tsx
import { createRef, type ChangeEvent, type FocusEvent } from "react";
import {
  Input,
  type ControllerFieldBinding,
  type TextControlHandle,
} from "./personal-ui";

const controllerField: ControllerFieldBinding<string, HTMLInputElement> = {
  name: "email",
  value: "person@example.com",
  onChange: (_event: ChangeEvent<HTMLInputElement>) => undefined,
  onBlur: (_event: FocusEvent<HTMLInputElement>) => undefined,
  ref: createRef<TextControlHandle>(),
};

const email = <Input controllerField={controllerField} />;
void email;
```

## Semantic theme tokens and Portal inheritance

Theme overrides are restricted to the exported semantic color-token allowlist. Geometry, spacing, control radii, z-index, and private selectors remain component-owned. Replace application CSS that reaches into `.pui-*` with `ThemeProvider` tokens.

```tsx
import { ThemeProvider, type ThemeTokens } from "./personal-ui";

const accountTheme: ThemeTokens = {
  "--pui-primary": "#1769d2",
  "--pui-primary-hover": "#125ab8",
  "--pui-focus-ring": "#1769d2",
};

const themed = (
  <ThemeProvider mode="system" tokens={accountTheme}>
    <AccountSettings />
  </ThemeProvider>
);
void themed;
```

Nested providers support `light`, `dark`, `system`, and `inherit`. Portaled overlays inherit the logical source provider's resolved tokens and mode; do not restyle the portal container or copy theme variables into application code.

## Composite forms and modal layer ownership

`Field` and composite controls own label, description, error, required, disabled, read-only, reset, FormData, and focus routing. Keep a stable `htmlFor`/control ID pair and pass validation through the documented component props rather than duplicating ARIA attributes on inner native elements.

All modal families now share one layer kernel for focus restoration, Escape/backdrop dismissal, inert ownership, scroll locking, nesting, Portal placement, and SSR-safe hydration. Dialog-family open state is controlled. Keep the launch button separate from the modal and update state through `onOpenChange`.

```tsx
import { useState } from "react";
import { Button, Dialog, Input } from "./personal-ui";

export function AccountDialog() {
  const [open, setOpen] = useState(false);
  return (
    <>
      <Button onClick={() => setOpen(true)}>Edit account</Button>
      <Dialog open={open} onOpenChange={setOpen} title="Edit account">
        <Input aria-label="Account name" />
      </Dialog>
    </>
  );
}
```

The Popover-family trigger migration below is the separate non-modal trigger ownership change.

## Locale provider and built-in messages

Built-in labels, fallback text, ARIA messages, dates, numbers, and plurals now come from the typed locale boundary. Existing consumers retain `zh-CN` when no provider is present. Add `LocaleProvider` when the product needs `en-US`, an explicit time zone, or a nested locale; business copy and submitted values remain consumer-owned.

```tsx
import { LocaleProvider, Pagination } from "./personal-ui";

const pagination = (
  <LocaleProvider locale="en-US" timeZone="America/New_York">
    <Pagination page={2} pageCount={8} onPageChange={() => undefined} />
  </LocaleProvider>
);
void pagination;
```

Locale keys are closed typed unions. Do not patch component source with translated strings or infer that changing display locale should reformat business values used for submission.

## Installation, upgrade, and rollback

Do not copy individual implementation files or edit an installed `src/personal-ui`. Run the installer from the canonical Skill checkout, inspect its deterministic dry-run, then perform the same mode against the explicit project root. `--force` is an upgrade acknowledgement, not permission to overwrite unrelated project files.

```text
python scripts/install_personal_ui.py --mode integrate --target <project-root> --force --dry-run
python scripts/install_personal_ui.py --mode integrate --target <project-root> --force
python scripts/verify_personal_ui.py --target <project-root>
```

The installer stages managed source and support files before replacement and restores the prior package/source bytes when an operation fails. Resolve dependency or unmanaged-file conflicts instead of bypassing the transaction. Package-manager, framework, workspace, project-root, and source-root support is limited to the verified M7 support matrix; a target status is not proof that a combination passed.

Release preparation is separate from installation. `scripts/release_personal_ui.py` changes candidate versions only inside isolated staging. Its guarded `publish --execute` phase requires authorization for the exact reviewed plan and completed evidence before it can create remote release artifacts or synchronize explicitly named installed copies.

The official M8 migration rehearsal is also separate from an application upgrade. It accepts only a release candidate whose release plan says the source is clean and bound to an immutable commit, whose verification journal is complete, and whose `publishable` decision is `true`. The runner requires the candidate support matrix and the local annotated tag object to identify the canonical `v0.2.19` commit `0587d4b08c1a70efff80c228b332f4064a7db6d1`; a different commit behind a lookalike tag is rejected. Candidate execution inputs are materialized from the already hash-verified candidate file map, checked again after the run, and never read from a mutable development checkout. All consumer work happens outside both the repository and candidate directory.

Preview the candidate-bound execution plan first, then use a new explicit output directory for the real run:

```text
python scripts/run_m8_migration.py --candidate <v0.3.0-rc.1-candidate> --print-plan
python scripts/run_m8_migration.py --candidate <v0.3.0-rc.1-candidate> --output <new-migration-evidence-directory>
```

No externally maintained pre-existing `v0.2.19` application is bundled with this repository. The checked-in `evaluation/m8/migration-v0.2.19-consumer` material is therefore a representative business fixture, not a claim about an external production project: the rehearsal first installs the starter exported from the exact old commit, then layers the fixture's login, form, table, overlay, data, configuration, styles, and workflow files onto that old starter. It builds and verifies this baseline before any candidate bytes are installed, exercises the browser workflow, applies the candidate upgrade, records the expected `Drawer.onClose` and `Popover.trigger` build failures, applies only the reviewed `onOpenChange` and `triggerLabel` source migrations, and repeats build, verifier, and browser checks. It also proves that consumer-owned files are preserved, modified managed files report a conflict, and an injected commit-stage installer failure restores the exact prior project bytes. A project newly installed from the candidate cannot satisfy this rehearsal.

Success writes `migration-report.json`, `artifact-inventory.json`, and hash-bound files under `artifacts/`, including before/after source archives, the reviewed migration patch, command records, screenshots, preservation/conflict/rollback reports, and candidate/baseline bindings. The inventory must exactly cover every review artifact and validates every byte by SHA-256. Failure exits with code `2` and writes `migration-failure.json` when the output directory already exists. A plan or report from a mutable/unverified candidate is not valid M8 evidence.

## Popover-family trigger ownership

`Popover`, `HoverCard`, and `Popconfirm` now own exactly one trigger button. Their former `trigger: ReactNode` prop could place a consumer button inside the component's button, producing invalid nested interactive markup and duplicate accessible controls.

Replace `trigger` with a non-empty plain-text `triggerLabel`:

```tsx
// v0.2.x
<Popover trigger={<Button>查看详情</Button>} ariaLabel="详情">
  ...
</Popover>

// v0.3.0
<Popover triggerLabel="查看详情" ariaLabel="详情">
  ...
</Popover>
```

The same mechanical change applies to `HoverCard` and `Popconfirm`:

```tsx
<HoverCard triggerLabel="预览成员" ariaLabel="成员预览">...</HoverCard>

<Popconfirm
  triggerLabel="删除成员"
  ariaLabel="删除成员确认"
  title="确认删除？"
  onConfirm={deleteMember}
/>
```

`triggerLabel` intentionally accepts only a non-empty `string`. Passing a React element through TypeScript, JavaScript, or `any` is rejected by the public type or runtime contract. Icon-only and custom-element triggers are not silently emulated; a future reviewed variant must preserve one interactive owner and the same ref, event, and accessible-name contract.

## GuidedTour target behavior

`TourStep.target` is now defined as a CSS selector evaluated in the logical source document while the step is open. A visible target receives a non-interactive spotlight and viewport-constrained adjacent card. An invalid selector, missing/hidden/removed target, zero-size target, or target outside the viewport falls back to the centered tour card without aborting the current step. Resize, captured scroll, relevant DOM mutation, and target/card resize trigger repositioning.

## AsyncSelect result ownership

For remote searching, prefer the new `loadOptions(query, { signal })` mode. It debounces queries (default 250 ms, configurable with `debounceMs`), aborts superseded requests, and ignores results that arrive after cancellation, closing, or unmounting. The loader must return options for its input query; it is mutually exclusive with the external `options` prop. Render loading, error/retry, empty, and disabled states through the component rather than inserting selectable sentinel options.

```tsx
<AsyncSelect
  ariaLabel="国家"
  value={country}
  onValueChange={setCountry}
  loadOptions={(query, { signal }) => fetchCountries(query, { signal })}
/>
```

The existing `options` mode remains available. If a parent fetches asynchronously, it owns cancellation/request generations and must pass `optionsQuery` with the exact query that produced those options. The component hides results while `optionsQuery !== query`; without this prop, externally supplied results are treated as current and cannot be distinguished from stale responses.

```tsx
<AsyncSelect
  ariaLabel="国家"
  query={query}
  onQueryChange={setQuery}
  options={results}
  optionsQuery={resultsQuery}
/>
```

The visible search control is a combobox while open; tests locating it as a `searchbox` should use its accessible combobox name. A closed selection trigger remains the named combobox.

## CodeEditor Tab ownership

`CodeEditor` now lets Tab and Shift+Tab follow normal focus order by default. To opt into indentation, set `tabBehavior="indent"`; in that mode Tab indents, Shift+Tab outdents selected lines, and Control+M temporarily switches between indentation and normal focus navigation. The shortcut is announced through the editor's accessible description and `aria-keyshortcuts`. Read-only, disabled, and IME composition do not intercept Tab. This remains a controlled plain-text textarea, not a syntax-aware IDE.

```tsx
// Former default behavior, now explicit:
<CodeEditor value={source} onValueChange={setSource} tabBehavior="indent" />

// New default: Tab leaves the editor.
<CodeEditor value={source} onValueChange={setSource} />
```

## Markdown source editor naming

`RichTextEditor` has always been a controlled plain-text textarea whose toolbar inserts Markdown markers. It does not render formatted content or provide a WYSIWYG document model. Use `MarkdownEditor` for that existing behavior. The props and controlled value remain the same; `RichTextEditor` and `RichTextEditorProps` remain as deprecated compatibility aliases, and mounting the old component emits a development warning. Discovery now uses `markdown-editor`; the former `rich-text` and `rich-text-editor` names resolve to the same entry only for migration.

```tsx
// Former misleading name:
<RichTextEditor value={source} onValueChange={setSource} aria-label="Notes" />

// Exact replacement, still Markdown source text:
<MarkdownEditor value={source} onValueChange={setSource} aria-label="Notes" />
```

The toolbar inserts `**bold**`, `_italic_`, Markdown list prefixes, and link syntax into the source value. It has no preview, Markdown parser, HTML rendering, or rich-document serialization. Consumers needing a WYSIWYG editor must use a separate, explicit implementation.

## VirtualList fixed row height

`VirtualList` uses fixed row-height arithmetic, not variable-height measurement. The old optional `estimateSize` prop implied an estimate that would be refined; rename it to `itemSize` (default 48 pixels) and ensure every rendered row fits that fixed height. `height` and `itemSize` must be positive finite numbers; `overscan` must be a nonnegative integer. The list clamps scroll position when items shrink, exposes a named Tab stop only while scrollable, and calls `onEndReached` once per tail identity (item count plus last item key). After a request fails without changing the tail, a consumer must explicitly change the dataset before automatic end loading can run again; `onEndReachedError` receives the rejection. The component does not offer variable-height measurement or an imperative focus/scroll-to-item API.

```tsx
// v0.2.x
<VirtualList items={rows} itemKey={(row) => row.id} renderItem={(row) => row.name} height={320} estimateSize={40} ariaLabel="记录" />

// v0.3.0
<VirtualList items={rows} itemKey={(row) => row.id} renderItem={(row) => row.name} height={320} itemSize={40} ariaLabel="记录" />
```

## TreeTable semantics and lazy rows

`TreeTable` is a semantic HTML table with keyboard-operable row disclosure buttons, not an ARIA `treegrid`. Tab visits the disclosure controls and any interactive cell content; Enter/Space expands or collapses. It does not promise arrow-key cell navigation. Lazy rows must set `hasChildren: true` when `children` have not been loaded, alongside `onRequestChildren`; supplying the callback alone no longer marks every leaf as expandable. A rejected request leaves the row collapsed and shows an inline error with a retry action. `getRowLabel(node)` supplies a useful name for each row's disclosure control; the stable node ID is the fallback when omitted.

```tsx
<TreeTable
  nodes={teams}
  columns={columns}
  treeColumnId="name"
  ariaLabel="团队"
  getRowLabel={(node) => node.value.name}
  onRequestChildren={loadTeamMembers}
/>
// For a lazy row: { id: "team-1", value: team, hasChildren: true }
```

## SortableList accessible item names

`SortableList` move buttons now include item identity and position, and a live status announces reorders. Add `getItemLabel(item)` for a human-readable name; without it, the stable `item.id` is used. Continue applying the `onReorder` result to the caller-owned items. Native drag-and-drop and the keyboard Up/Down buttons remain the supported modes, not cross-list dragging.

## DragDrop accept filtering

`DragDrop.accept` previously appeared in a data attribute but forwarded every file. It now filters the callback payload using file extensions and MIME rules; `onRejected(files)` can report files excluded by `accept`. It remains a drop-only surface with a named group, not a keyboard file picker or network uploader. Use `FileUpload` when users need browse, validation, status, and keyboard selection.

## InfiniteScroll cursor identity

`InfiniteScroll` now requires `loadKey: string | number`. The caller owns the fetch, cursor, `loading`, and `hasMore`; pass the current page or cursor identity as `loadKey` and advance it only when new content or a retry batch is ready. The observer requests at most once per key, including after a failed request. Without this key, the old in-flight-only latch could repeatedly fetch an unchanged page; an omitted key now fails at the type boundary and throws at runtime in JavaScript.

```tsx
<InfiniteScroll
  loadKey={nextCursor}
  hasMore={hasMore}
  loading={loading}
  onLoadMore={fetchNextPage}
  onLoadError={reportError}
>
  {items}
</InfiniteScroll>
```

This is an observer-only trigger, with no built-in manual-load fallback when `IntersectionObserver` is unavailable. Use `LoadMore` as the explicit button model when that behavior is required; do not mount both for the same fetch surface.
