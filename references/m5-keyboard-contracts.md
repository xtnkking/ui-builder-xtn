# M5 Keyboard Contracts

This is the M5-07 working-tree contract, not a release or whole-stage acceptance declaration. The tables describe the supported keyboard surface as implemented on 2026-09-21. A linked test file identifies a test, not proof of every edge or a fresh passing run. `-` means there is no dedicated evidence of that kind. Axe checks semantic violations; they do not prove the keyboard sequence, focus ownership, or scroll behavior. The [capability audit](component-capabilities.md) records the separate feature/name decisions, and the [M5 execution plan](v0.3.0-m4-m8-execution-plan.md) sets the stage gate.

Most tables below retain the 2026-09-21 snapshot. The DragDrop and InfiniteScroll rows now follow the [2026-10-10 standalone command contract](#standalone-commands-2026-10-10), which supersedes their earlier drop-only and observer-only limitations. The [2026-10-09 composition addendum](#official-compositions-d2d3-2026-10-09) remains evidence for the optional shared-state workflows at their actual revisions.

## Standalone Commands (2026-10-10)

DragDrop and InfiniteScroll now include their keyboard commands directly; a separate companion is optional. Their default Explorer routes compile the standalone examples. Existing shared-queue examples explicitly disable the corresponding built-in action (`showBrowseButton=false` or `showLoadMoreButton=false`), keeping exactly one keyboard action owner per workflow.

DragDrop's default `multiple=true` accepts every file matching any accept rule. `multiple=false` accepts the first matching file and reports all incompatible or additional files through `onRejected`. Both chooser and drop use this same policy. The chooser input resets after each change so the same file can be selected again. It is hidden from accessibility and sequential focus; only the canonical Button is a stop. No transport, queue, size limit or OS dialog focus guarantee is introduced.

InfiniteScroll's manual and observer paths acquire the same synchronous request latch before user code runs. A successful loadKey is requested once; callers advance loadKey when adopting the next cursor. A rejected key exposes the localized error message and changes the same button to Retry. Observation does not retry a failed key automatically. Enter/Space retries that key, preserving caller-owned records. Loading, controlled loading, disabled and hasMore=false all block new actions; a throwing onLoadError observer cannot produce an unhandled rejection. At the end, the mounted button retains existing focus but has `aria-disabled=true` and `tabIndex=-1`, allowing Tab to continue to the following action without a lost focus node.
