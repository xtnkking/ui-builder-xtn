### 1.2 必须保留的产品约定

以下是本轮重构的回归边界，不是要求额外重做这些功能。数值以当前组件源码和已认可的实例为准。

- 页面使用注册的公开组件和页面模式；不改为第三方控件、业务页自绘原生控件或复制一套相似 CSS。发现缺失能力应修复权威组件并补齐注册和验收。
- 保留蓝色主色、既定控件高度与圆角、轻巧胶囊按钮/标签、状态切换尺寸稳定的视觉体系。错误态不能叠加蓝色光圈或额外粗边；密码眼睛、清空按钮不能重复或错位。
- `FilterBar` 默认无额外背景区域；搜索、筛选由明确提交按钮触发，输入条件本身不频繁请求。涉及加载的操作使用组件加载态。
- 表格保留稳定视口高度、加载/空数据不跳高、分页和无分页两种模式、排序与列显隐；冻结由开发者配置，勾选列场景保留默认冻结勾选列和首个数据列的规则及已有覆盖选项。
- 表格表头、表体、滚动条、底边与四角保持已修复关系；不得通过添加白边、遮挡内容或改变冻结偏移掩盖问题。
- 右侧抽屉桌面默认上、右、下贴边，仅左上/左下圆角；保留已有非默认悬浮模式。重构浮层行为不能退回旧的默认留缝样式。
- 遮罩点击、右上角关闭、Esc 是三个独立关闭策略；关闭后再打开仍然生效。键盘可见焦点保持可用，但不能让整块弹窗出现意外蓝圈。
- Toast 的位置、圆角/胶囊、关闭按钮和倒计时配置保留独立性；标签选中前后不因图标出现而改变宽度。

### 1.3 范围和执行纪律

1. 一次推进一个任务编号；阶段内可拆独立子任务，不并发修改同一内核、API 报告或生成文件。
2. 每项交付必须同时对齐实际源码、公开类型、校验器、必要示例和文档。禁止只加文字要求来冒充组件能力。
3. 新增内部模块可以；增加无关组件家族、替换技术栈、重新设计整套 UI 不在本计划内。`LocaleProvider` 是原路线图明确要求的新增公开能力。
4. 已知缺陷先用最小回归证明，再修复；待核实能力先检查契约与行为，不能把静态怀疑写成已复现故障。
5. 不删除测试、不放宽来源校验、不盲目刷新视觉基线来换取通过。合法 API 调整更新兼容报告和迁移说明，不覆盖不可变基线。
6. 常规修复自行完成；只有范围改变、无法推断的产品选择和公开发布需要另行决定。用户已选择 MIT License，后续不得静默替换。

## 3. M4：表单与浮层内核

### M4-01：确定复合控件表单协议

- **现有入口**：`inputs-extra.tsx` 的 `FormValueBridge` / `FormValuesBridge`，`value-controls.tsx` 的重复桥接，`forms.tsx` 的 `useFieldControl` / `Field` / `Select` / `Combobox`，`date-field.tsx`、`contracts.ts`、`internal/control-handles.ts`。
- **已确认结构问题**：现有桥把 `required` 放在 hidden input；hidden input 不参加原生约束校验，而且部分桥在没有 `name` 时完全不渲染。提交字段与校验职责需要分开。
- **修改**：先列出所有桥接调用者与标量/多值/日期等值类型，确定统一内部协议：字段归属、当前值、初始值、序列化、有效性、可见焦点目标、失效/重置事件。不得给每个组件再各写一套。
- **拟新增交付**：内部复合表单模块，以及 `references/form-contract.md`。复用 M2 的受控状态工具、受限 `controlRef` 和官方表单库适配器，不恢复 DOM `ref` / 任意样式逃生口。
- **验收**：文档明确无 `name` 但 `required`、外部 `form`、禁用/fieldset 禁用、只读、受控/非受控 reset、校验失败聚焦、空多值如何处理；接口有类型用例，不存在矛盾属性组合。

### M4-02：实现提交、必填与错误聚焦

- **修改**：让复合控件真实参与表单提交与验证。hidden input 可以承担成功字段序列化，不能承担 `required` 的验证证明；根据原生约束验证与 form 事件设计有效桥接，并在真实浏览器验证。
- **必须实现**：空必填阻止普通提交和 `requestSubmit()`；有效值可提交；`checkValidity()` / `reportValidity()` 与受限 handle 的已声明行为一致；错误定位到可见 owner，不出现“invalid form control is not focusable”。不能拦截或重新定义原生 `form.submit()` 本身绕过校验的浏览器语义。
- **序列化规则**：标量一次、多值以已约定的重复键表示、空值策略明确；与原生字段混用不重名重复写入；disabled 字段不参与成功字段，`new FormData(form)` 与实际提交一致。日期值使用明确格式，不能依赖显示语言解析。
- **验收样例**：未命名必填、空多选、选中后取消、原生与复合字段混合、外部 form、禁用后恢复、服务端错误、清错后重验。Chromium/Firefox/WebKit 都必须验证真实提交和可见控件焦点。

### M4-03：迁移所有调用者并补齐 reset / 适配器

- **修改**：迁移 M4-01 清单内全部复合控件，删除重复桥实现；将 Field 的 label、description、error、`aria-invalid`、`aria-describedby` 与统一协议关联。
- **受控规则**：非受控 reset 回到初始值；受控 reset 通过约定回调请求外部状态更新，父级拥有最终值，不可私自改 DOM 造成显示/提交分离。默认值更新和重置基准必须有明确契约。
- **回归入口**：`tests/components/form-control-contracts.test.tsx`、`inputs-extra-contracts.test.tsx`、`value-controls-contracts.test.tsx`、`form-library-adapter.test.tsx`，以及对应类型测试；新增真实 React 表单浏览器 fixture。
- **完成标准**：所有桥调用者都使用同一协议；标量/多值、受控/非受控、disabled/reset/external form 全覆盖；三引擎的必填、FormData、焦点结果一致。示例能直接复制到消费者项目。

### M4-04：提取并补齐共享浮层内核

- **现有入口**：`overlays.tsx` 的 `modalStack`、`usePortalReady`、注册/注销、`useModalBehavior`；`portal-tokens.ts`、`floating-position.ts`、`internal/overlay-slots.tsx`。
- **修改**：提取现有实现并补齐，不从头重写。内部内核统一注册顺序、初始焦点、Tab/Shift+Tab 圈定、Esc 顶层处理、焦点恢复、背景 inert、滚动锁引用计数、dismiss 原因和 Portal 主题。
- **关键边界**：区分模态和非模态层；弹窗内 Select/Popover 等 Portal 属于当前层的允许交互分支。不能把 body 整体 inert 导致弹窗自己失效；仅禁用实际背景并恢复原先的 inert/滚动样式。
- **生命周期**：覆盖重开、动画退出、StrictMode 重挂载、嵌套父层先卸载、触发器已被移除、无可聚焦元素、两个独立浮层树；事件与观察器必须释放。
- **SSR**：模块加载/首屏 render 不无条件访问 window/document；Portal 容器和主题在客户端确定后挂载，服务端和 hydration 无错配。使用合适的 ownerDocument，不假设所有内容都在同一全局 document。
- **拟新增交付**：内部 layer 模块和 `references/overlay-contract.md`；不暴露任意 z-index/style 破坏 M2/M3 的约束。

### M4-05：迁移 Dialog / Drawer / ConfirmDialog

- **现有入口**：`overlays.tsx` 的 Dialog、Drawer；`overlays-extra.tsx` 的 ConfirmDialog。
- **修改**：三个组件接入内核；公开外观、既定默认值和抽屉贴边圆角不变。将关闭入口映射到统一原因，清理捕获旧 Props 的监听器。

- **焦点验收**：打开进入合适控件，Tab 不逃出，关闭回到仍可用的触发器，否则使用约定回退；关闭/卸载后页面滚动与 inert 恢复，原页面状态不被覆盖。

## 4. M5：复杂控件键盘模型与真实能力

### M5-01：Tree / TreeSelect

- **现有入口**：`data-extra.tsx` 的 Tree，`inputs-extra.tsx` 的 TreeSelect。后者使用 M4 的表单与浮层协议。
- **修改**：建立基于稳定节点 key 的可见扁平序列与 roving tabIndex 状态机；记录 ArrowUp/Down、ArrowLeft/Right、Home/End、Enter/Space 的精确定义，区分聚焦、展开和选择。
- **ARIA**：tree/treeitem/group 层级与 expanded/selected/checked 等语义按实际选择模式分配；仅当前焦点项进入 Tab 序列，不让每个节点的装饰/箭头重复成为 Tab 停点。
- **边界**：折叠祖先、删除活动节点、筛选结果变化、disabled/all disabled、受控选择、多选/级联（仅覆盖实际支持的模式）；活动节点失效时有确定回退。
- **验收**：纯键盘完成展开、导航、选择和退出；disabled 项不能成为活动/选择目标；类型、行为测试、axe 和使用示例一致。

### M5-02：Calendar / DateField

- **现有入口**：`data-extra.tsx` 的 Calendar、`date-field.tsx`。先明确日历网格与不同日期精度面板的归属，不把所有模式硬塞进同一日网格。
- **修改**：正确的 grid→row→gridcell/columnheader 结构；一个预期日期 Tab 停点，方向键移动日期，Home/End 与月份导航按文档定义；日期跨月后焦点跟随，年月变化与选中状态可被读屏获知。
- **边界**：min/max、disabled 日期、跨年/闰年、空值、受控值外部改变、时区边界；保留年、年月、年月日、日期时间等当前已支持精度及显示/提交格式。
- **验收**：不使用指针也能完成选择并返回触发器；不可选日期不能被激活；网格语义有效，三引擎的关键导航和真实焦点通过。国际化文案接口留给 M6 接入，不在此另造一套字典。

### M5-03：ContextMenu

- **现有入口**：`overlays-extra.tsx` 的 ContextMenu。
- **修改**：右键位置打开，ContextMenu 键/Shift+F10 在所属触发器处打开；上下/Home/End 导航、Enter/Space 执行动作、按字母查找、Esc 和点击外部关闭。
- **语义与边界**：菜单项稳定 id 和名称；跳过 disabled 项；视口边缘定位；键盘打开与鼠标打开使用同一选择状态机。仅对实际支持的子菜单实现左右键，不声称不存在的子菜单能力。
- **验收**：执行/取消后焦点归位，嵌套浮层内不误关父层；无原生菜单与组件菜单同时出现；纯键盘和 axe 用例均通过。

### M5-04：AsyncSelect

- **现有入口**：`inputs-extra.tsx` 的 AsyncSelect、`floating-position.ts`、现有异步下拉浏览器回归。当前以 index / data-active 管理活动项，需要完整语义与稳定标识。
- **修改**：combobox 的 controls/expanded/autocomplete/activedescendant 与 listbox/option 对应；保持输入框焦点，按稳定 key 管理活动项，滚动确保活动选项可见。
- **异步处理**：搜索去抖与取消/请求代次（选择合适机制），旧请求不能覆盖新结果；快速输入、清空、重新打开、卸载、返回乱序、结果重排/删除后活动项与选值正确协调。
- **状态**：loading/error/retry/empty 有可访问反馈但不是可选 option；disabled/过期结果不能激活；中文输入法组合期间不误提交、不误选项。保留国家旗帜/缩写/区号等结构化选项呈现。
- **验收**：通过人为控制 Promise 返回顺序证明结果不会倒退；验证 value 与显示标签、FormData 一致；键盘选择、删除/清空、关闭重开和弹窗内选项 Portal 回归通过。旧响应覆盖在实测前只能标为待验证风险。

- **升级契约**：记录安装版本和受管理文件，比较源哈希；区分干净托管文件、用户修改、无关业务文件。默认不覆盖冲突，提供明确计划和迁移诊断，不能通过 `--force` 清空整棵目录。

- **事务**：预检→staging→验证→应用→确认；对复制、JSON 更新、依赖安装、门禁失败等位置做故障注入，恢复受本次操作修改的文件与目录，不影响并行用户修改或已有无关文件。
- **验收 fixture**：至少包含全新安装、重复安装、从 v0.2.19 升级、自定义 source root、工作区子包、源码冲突、半途失败、权限/路径错误、重复 dry-run；验证失败后与操作前文件清单/哈希一致。
- **安全边界**：禁止对家目录/仓库根执行递归清空，禁止用 `/MIR` 粗暴同步；旧文件只在清单明确归属本工具且目标已验证时处理。备份恢复也不能覆盖任务外新文件。

### M7-06：一个发布编排入口，区分本地准备与公开发布

- **现状**：`npm run release:check` 只验证，不负责版本、打包、同步、tag 或 GitHub Release。
- **拟新增能力**：一个 release orchestrator，包含 prepare/verify/publish 阶段和无写入 dry-run。具体命令名实现后再写入 README；不能在未实现时要求接手者运行想象中的脚本。
- **本地 prepare**：指定冻结源快照与目标版本，在隔离 staging 中更新版本/兼容报告/完整性→验证→构建→安装 fixture→打包→SHA-256→发行说明→同步/标签计划；生成可复现 RC，不先改已安装副本或远端。
- **一致性**：稳定文件排序、归档时间策略与依赖锁定；包内包含 Skill、组件、Manifest、校验工具、必要文档/许可证，不含 node_modules、缓存、密钥、测试临时文件。两次干净构建可比较内容和校验和。
- **失败恢复**：本地准备失败不能遗留新版本或 tag；公开动作前先完成全部检查。远端发布不是可原子回滚的文件事务，需逐步记录与安全恢复/续跑，不擅自重写已公开 tag。
- **publish**：仅在最终用户明确授权后执行冻结提交/版本、不可变 tag、GitHub Release、附件、checksums 和已指定生成副本同步，核对实际 tag 指向的源码与已审阅 artifact 一致。
- **同步**：权威源码单向到已安装/备份目标，记录来源 commit/版本/哈希；预检差异，保护无关用户文件。旧指令中的历史“发布吧”不等于本轮 v0.3.0 最终审阅授权。
- **验收**：同一编排入口可复现本地发行物、只读预演和失败恢复；不得把验证命令的成功表述成已创建 GitHub Release。

### M7-07：版本历史、迁移、许可证与阶段收口

- **版本历史**：从真实 tag/commit/Release/现有 CHANGELOG 重建可证实的变更，逐版记录新增/修改/修复/破坏性变化和升级说明。无法核实的历史明确标注，不能编造日期、版本或修复内容。
- **当前发布记录**：集中整理 M0–M7 的用户影响，准备 v0.3.0 发行说明；本轮未发版工作记在明确的未发布区域，不把旧 `0.2.19` tag 描述成包含新代码。
- **SemVer 规则**：明确 patch/minor/major、0.x 阶段破坏性变更、RC 到正式版的判定规则；与 `api-version-policy.json` 和 API 兼容检查保持一致，由发布编排拒绝不匹配的版本选择，不能只把规则写在 README。
- **API 迁移**：包含 M2 的受限 Props/ref/受控契约、M3 token/主题、M4 表单与 trigger、M5 能力更名/键盘默认值、M6 locale、M7 安装路径和升级命令；提供能编译的前后示例与自动诊断。
- **许可证**：用户已明确选择 MIT License；根 LICENSE、React starter metadata 与 Skill frontmatter 保持一致。`THIRD_PARTY_NOTICES.json` 已与 lockfile 的 176 个唯一依赖版本精确对齐，发布门禁会拒绝重复、缺失、额外或元数据不匹配的条目。
- **通过条件**：公共入口稳定或有迁移说明，CSS 门禁生效，安装/升级/回滚矩阵通过，干净源码可复现产物，dry-run 不写入，失败不留新版本/tag；源码/包/Manifest/API/哈希一致。更新 M7 账本后进入 M8。

## 8. 测试与生成规则：证明变更，不陷入全量循环

### 8.1 每个任务的最小闭环

1. 读取当前任务列出的源码入口、相关测试和公开契约，写下这一项需要改变的行为；不要重新做一次全库架构评估。
2. 对已知缺陷补一个能失败的最小回归；对迁移/能力补齐选择合同测试、类型或浏览器层中真正能证明问题的一层，不写只复述实现的测试。
3. 修改组件或工具，运行该任务的聚焦测试。需要原生表单、焦点、键盘、滚动、Portal、SSR 的行为不能仅用 jsdom 证明。
4. 检查公共 Props/状态/来源校验是否受影响；有公开接口变化才补类型、API/兼容和迁移证据，有几何变化才重跑相关视觉用例。
5. 记录实际命令、结果、源码快照与下一项。完成任务就向前推进，不为了“更放心”重复同一套已经通过的测试。

### 8.3 阶段门禁和失败处理

- 阶段内采用聚焦检查；阶段收口统一刷新该阶段改变的完整性、API、兼容报告、覆盖等生成物，再运行一次完整 `release:check`，按当前阶段接受标准补齐它尚未包含的必要证明。
- 一次完整门禁中如果某项失败，保留已通过结果，定位首个真实原因，修复后只重跑失败项及受其变化影响的检查；不要从第一项无限重新执行。依赖图、公共内核或构建配置变化才扩大验证范围。
- 同一失败在两次针对性修复后仍复现，应停下全量重试，收集最小复现/日志和假设，换诊断方法或推进不依赖此项的工作；不得标通过、放宽断言或永久挂起整个计划。
- 记录测试环境/浏览器版本和影响文件。保存旧通过结果不代表把旧源码的结果当作新源码通过；只有能说明未受影响的证据可复用。
- 浏览器一次性安装依赖、下载或启动失败与产品缺陷区分记录。真实 Safari/托管 CI 等环境不足标明“待验证”，不要反复重跑本机套件试图替代。
- 视觉差异先人工/图像核对是否符合已认可的外观，只有经确认的有意变化才更新受影响基线；跨操作系统字体差异也需记录，不能直接全量刷新。
- 最终候选冻结后做一次干净环境的完整发布验收；之后代码变化需按影响补证。M8 独立消费测试不由内部 demo 的全绿代替。
